Music Atlas

The Map as Data

The map's structure and descriptions as one JSON file, for handing to a language model.

musicatlas.us/musicatlas.json · about 187 KB

https://musicatlas.us/musicatlas.json

What It Is For

Give the address to a model and ask where to go next from something you already like. The lineage lets it say why two styles are related, not only that they are. Every style carries the address of its own panel in the atlas, so an answer can link to what it names.

What Is in It, and What Is Not

Every style, its year, family, parents and children, its description and its atlas URL. There are no artist lists and no song titles: those are most of the bytes, they already sit in the app behind each playlist, and a file too big to fetch is no use to a model.

The file carries its own note to the reader (readMe) on what a link does and does not claim. Coverage is uneven: not every style has a playlist, and absence from the file is not evidence that something does not exist.

It is regenerated from the map on every deploy by tools/catalog.js.

How the Atlas Is Built

One HTML file, with nothing fetched while it runs, so it keeps working with no connection; playlists open in Apple Music, Spotify or Qobuz, which do need one. The icons are Phosphor, MIT licence, inlined as paths. Everything else was drawn or written for the atlas.
